> ⚠️ **隐私说明（请先看）**：本插件会在本地缓存**最近 40 条左右的聊天文本**
> （`data/plugin_data/astrbot_plugin_qzone_kit/state.json` 的 `recent` 字段），

>
> 自己发说说时，也会把攒下来的内容先发给同一个模型做「挑一挑」，
> 同样只在本地发起、不经过第三方存储。

## 主要功能

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | **删说说** | 「删第 3 条」（按时间由近到远）、「把昨天的说说都删了」（今天/昨天/前天/大前天/具体日期，整批删） |
| 2 | **改资料** | 昵称 / 签名 / 在线状态 / 头像（直接走 OneBot 接口，不依赖别的插件） |
| 3 | **手动发一条总结** | 「现在就发一条说说」——复用 QQ空间插件那套读聊天、写稿的逻辑 |
| 4 | **自动改签名** | 她自己判断心情/目标/兴趣变了就换；平时 **13~32 天**一次，非常重要 **22~29.2 小时**；冷却没过就记下来，新的覆盖旧的 |
| 5 | **自动发说说** | 发泄 / 被安慰 / 新鲜事 / 重要事 / 想记录 / 有感触时发；平时 **2~3.6 天**一条，非常重要 **22~29.2 小时**；不重要的小事**攒着合成一条**；**3 天没发就保底发一条**日常；**75%** 概率带表情包（来自「表情包管理器」的全部图包，GIF 动态原样发）；会自动躲开「每天那条总结」（见下） |

## 五个工具（模型能直接调）

| 工具 | 干什么 | 使用者怎么说 |
| --- | --- | --- |
| `qzone_delete_feeds(pos, date_text)` | 删说说：`pos=1` 删最新那条（由近到远）；`date_text=昨天` 整批删 | 「删第 3 条」「把昨天的都删了」 |
| `qq_profile_update(field, value)` | 改资料：昵称 / 签名 / 状态 / 头像 | 「昵称改成泡泡」「状态换成摸鱼中」 |
| `qzone_post_summary()` | 立刻发一条「今天的总结」（复用 QQ空间插件的写稿） | 「现在就发一条说说」 |
| `qq_signature_maybe_change(text, importance)` | 她**自己想**换签名（受冷却管） | 不用人说，她自己会调 |
| `qzone_mood_post(content, importance, sticker)` | 她**自己想**发说说（受冷却 + 攒批管） | 同上 |

`date_text` 支持：`今天` `昨天` `前天` `大前天` `2026-11-03` `11-03` `11月3日`。

## 三个自动开关（默认都开，配置时问使用者）

| 开关 | 配置键 | 默认 | 作用 |
| --- | --- | --- | --- |
| 每天自动发说说 | `daily_post_enabled` | 开 | QQ空间插件那条 **23 点「今天的总结」**；关掉会停掉它的 AutoPublish |
| 自动改签名 | `auto_signature_enabled` | 开 | 她自己判断心情/目标变化就换签名（平时 13~32 天） |
| 自动发说说 | `auto_post_enabled` | 开 | 有情绪/有事的即时说说（2~3.6 天，带攒批与保底） |

另外还有一个**可选项**：`post_sticker_enabled`（配图），默认 **关**，**要使用者明确同意才开**；
开了之后默认 **75%（高概率）** 配图，来源是「表情包管理器」里的图（所有图包）。
**这个概率是全局统一的**：她自己发的说说、以及每天 23 点那条「今天的总结」，都按同一个概率带图；
想调频率就改 `post_sticker_prob`（0 = 永不配图，1 = 每条都配）。

## 两个「自动」是怎么跑的

后台每 `judge_interval_minutes`（默认 45 分钟）看一眼最近的聊天，问一次模型：

> 她现在的状态变了吗？值得发一条说说吗？

拿到 JSON 之后按冷却决定「现在就做 / 先记着」。**冷却都是区间随机**，不是整点：

| 场景 | 区间 |
| --- | --- |
| 改签名 · 平时 | 13 ~ 32 天 |
| 改签名 · 非常重要 | 22 ~ 29.2 小时 |
| 发说说 · 平时 | 2 ~ 3.6 天 |
| 发说说 · 非常重要 | 22 ~ 29.2 小时 |
| 保底 | 3 天没发说说 ⇒ 下一轮要求它必须发一条 |

- **签名**：冷却没过就存进 `pending`，**新的覆盖旧的**（只留一条），到点自动换上。
- **说说**：冷却没过就**攒着**（最多 5 段）；到点发车时——
  - **不超过 3 条**：直接全部合成一条发；
  - **超过 3 条**：先让模型挑一遍（重要性 + 新鲜度），**挑完发 3~5 条**，具体几条它自己定；
    太旧又无关紧要的就不发了。再来的新片段跟着这批走，不推迟发车时间。
- **表情包**（可选，默认开 75%）：从「表情包管理器」(`meme_manager`) 图包里按语义分类挑，**GIF 动图原样发**（空间会保动画），其它格式转 JPEG；**带图发布失败会自动退回纯文字**，不会丢说说。

## 和「每天那条总结」不撞车

每天的「今天的总结」是 QQ空间插件的 AutoPublish 在发（默认 23:00），所以自己发说说之前多了一道检查：

- **抽到点时间时就避开**：给「攒着的那批」定时间，如果落进「每天总结」**前后各 1.5 小时**
  （默认 21:30~00:30），就**重新抽一个**，直到不落在里面为止——不往后推几个小时。
- **现在就发**的另算：只避开总结前后 15 分钟，撞上了就往后挪半小时，不会等上几小时。
- 就这样，没有别的花活：不记录在线时段，也不预设活跃时间段。
- **几点算「每天总结」**：`daily_post_time` 默认 `23:00`，改它 QQ空间插件的 AutoPublish
  **立刻就跟着改**（运行中重排 + 写回 `publish_cron`，重启也还是这个点）；
  反过来在 QQ空间 插件那边改了时间，这边也会跟着变过来（不会把人的设置按回去）。
  真把 `daily_post_time` 清空的话，就退回"每次现读 `publish_cron`"。
- 半夜不拦：0 点以后她想发就发，只是**写的时候要跟现在的时间对得上**——
  合成说说时会把【现在时间】（含时段称呼）喂给模型，凌晨写的碎片到了别的时间发，会顺着改成那时的说法。
- 老大**点名**让她发（`qzone_post_on_demand` / 手动发总结）不受这个限制，说发就发。

## 没开机 / 错过了怎么办

**每天那条总结：过了就是过了，不补。** 它是 QQ空间插件的一次性定时任务，电脑关着、没跑到，那天就没有总结；
补发的话正文里的「今天」说的其实是昨天，时间戳却是第二天早上，读起来很怪。所以只会在**正在跑且发失败**时 10 分钟后重试一次。

**她自己想发的：开机后补。** 到点时间存在 `state.json` 里，但不会一开机就发：

| 情况 | 怎么处理 |
| --- | --- |
| 开机 / 重载插件 | 先等 `post_boot_wait_minutes`（默认 3 分钟，等 CQHttp 绑好），再随机多等 2~60 分钟，才检查攒着的 |
| 撞上每天总结的时间窗 | 生成时间时就避开：挪到窗口结束后（+随机几分钟），最长等这一整个窗口 |
| 攒的碎片太旧 | 超过 `post_max_age_days`（默认 5 天）的直接不发 |
| 全过期了、没东西可发 | 那天就不发；但按「已经发过」处理，直接进下一轮冷却，不会一开机就补一堆陈年旧事 |
| 补发时内容属于前几天 | 合成时把时间喂给模型，要求写「昨晚」「前两天」，不许写「今天」 |

## 说说的排版

她的说说会分成 **2~3 段**，不再是一大块：

- **生成阶段**就要求「分 2~3 段，每段 30~150 字，段与段空一行」；
- **发之前**如果还是一整块，就自动按句子分 2~3 段；她自己分好段的话保留原样；
- 想调：`post_paragraphs`（默认 3）、`post_paragraph_chars`（默认 100，30~150）、`post_max_chars`（180）；
- 想关：`post_format: false`。

## 状态文件

`data/plugin_data/astrbot_plugin_qzone_kit/state.json`

- `signature.last_at / last_text / pending`（上次改的时间、内容、待换的）
- `post.last_at / pending / pending_due`（上次发的时间、攒着的、到点时间）
- `recent`（最近聊天，判断材料）

删掉它 = 重置所有冷却和待发。

## 踩过的坑（都是实打实踩的）

1. **提示词里的 JSON 花括号**：判断模板里有 `{"signature": ...}`，用 `str.format()` 会 `KeyError('"signature"')`，循环每轮崩、永远不发。改成 `[[占位符]]` + `replace`。
2. **AstrBot 会删掉 schema 里没有的配置键**（日志 `Config key removed`）：新加的配置键必须同时写进 `_conf_schema.json`，否则读到永远是默认值。
3. **带图说说发不出去**：QQ空间的 `normalize_images` 用 `urlparse` 解析图片路径，Windows 的 `D:\...` 会被当成协议 `d` 丢掉 → 0 张图 → `code=-10061`。修法见 `SETUP-FOR-AI.md` 第 4 节（给 `download_file` 打本地路径优先的补丁）。
4. **`Post` 模型只收字符串路径**：传 `bytes` 会在 `Post(...)` 校验时报 `1 validation error for Post`，别走这条路。
5. **改头像必须给图**（发图或图片链接）；**删说说按日期是整批删、不可撤销**。
6. **GIF 动图不用转静态**：实测 QQ 空间的 `cgi_upload_image` 收 GIF 是保留动画的——
   发出去再抓回来还是 `GIF89a`、帧数不变（Qzone 会把图压缩成缩略图，但动画还在）。
   所以 GIF 现在**一律原样发**，多大都不转，别再抽第一帧了；真传不上去会退回纯文字，不会丢说说。
7. **AstrBot 存的配置 json 带 BOM**：读别人的配置文件要用 `utf-8-sig`，不然
   `JSONDecodeError: Unexpected UTF-8 BOM`，会静默退回默认值。
